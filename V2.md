# V2 tasks

## Election-window reliability

- [x] Parse `datetime-local` election start and end values in the administrator-selected IANA timezone (for example, `Africa/Lagos`) before saving them as UTC timestamps. Do not rely on the server's local timezone.
- [x] Automatically transition an election from `open` to `closed` when its end time passes, using a reliable scheduled server-side process.
- [x] Ensure the admin election list and dashboard treat an election whose `endsAt` is in the past as closed even if the background transition has not yet run.
- [ ] Keep the existing server-side ballot checks for `startsAt`, `endsAt`, and election state on ballot load and submission; add coverage for timezone boundaries and expired-election submission attempts.

## Admin and voter role separation

- [ ] In production, prevent an email address assigned to an admin account from voting, even if the same email appears in an election's voter register. Enforce this on the server across voter OTP verification and ballot access/submission, using normalized email comparisons; do not rely on hiding or disabling UI controls.

## Results and audit exports (deferred)

- [ ] Let authorized admins download a final election report containing aggregate vote totals, turnout, winners or ties, and a non-sensitive audit summary. Never include voter identities alongside ballot choices.
