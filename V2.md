# V2 tasks

## Election-window reliability

- [x] ✅ Parse `datetime-local` election start and end values in the administrator-selected IANA timezone (for example, `Africa/Lagos`) before saving them as UTC timestamps. Do not rely on the server's local timezone.
- [x] ✅ Automatically transition an election from `open` to `closed` when its end time passes, using a reliable scheduled server-side process.
- [x] ✅ Ensure the admin election list and dashboard treat an election whose `endsAt` is in the past as closed even if the background transition has not yet run.
- [ ] Keep the existing server-side ballot checks for `startsAt`, `endsAt`, and election state on ballot load and submission; add coverage for expired-election submission attempts.

## Admin and voter role separation

- [ ] In production, prevent an email address assigned to an admin account from voting, even if the same email appears in an election's voter register. Enforce this on the server across voter OTP verification and ballot access/submission, using normalized email comparisons; do not rely on hiding or disabling UI controls.

## Results and audit exports

- [x] ✅ Let authorized admins download final reports for any published election from the report archive. Include aggregate vote totals, turnout, winners or ties, and a non-sensitive audit summary. Never include voter identities alongside ballot choices.

## Before a real election

- [ ] Implement and verify a scheduled retention process that purges or anonymizes eligibility, OTP, and security records after one year while preserving anonymous aggregate results and necessary non-identifying audit records.
- [ ] Add automated unit, integration, end-to-end, and security regression coverage for election rules, role access, OTP handling, CSV imports, ballot anonymity and one-vote enforcement, results, exports, and privacy-safe error handling. Run the checks in CI.
- [ ] Run a complete mock election in staging using synthetic voter data. Rehearse voter imports, candidate setup, opening and closing, voting on web and mobile, OTP delivery failures, result publication, exports, tie handling, and early closure.
- [ ] Load test the OTP and voting flows at expected peak volume for up to 5,000 students, using synthetic data.
- [ ] Approve and document department procedures for tied results, disputes, early closure, election cancellation, and communicating final results.
- [ ] Verify isolated staging and production databases, provider credentials, environment variables, backups, and rollback procedures before production use.
- [ ] Complete mobile release preparation: app store listings, signing credentials, privacy/data-safety disclosures, support contact, privacy policy URL, and reviewer test instructions.
- [ ] Configure operational alerts for OTP delivery failures, abnormal verification failures, ballot submission errors, database/API outages, and provider quota limits; document incident contacts and response steps.
- [ ] Enable provider quota alerts separately in the Resend, Vercel, Neon, and Cloudinary dashboards. These dashboard settings are not configured by app code.
